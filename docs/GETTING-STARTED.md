# dsh-gopeed 上手指南

> 本手册面向中文用户（人工阅读）。agent 请阅读 [README.md](../README.md)。

> 本文面向「只装了干净的 DSH、从没装过 Gopeed」的用户。全程不需要命令行，照着点即可。

## 这份文档能帮你做什么

装好 Gopeed、配置好它的接口地址和端口、在 DSH 里启用 `dsh-gopeed` 插件，然后你就可以直接对 agent 说「下载这个链接」，不必自己打开下载软件。照着做大约 10 分钟。

## 第 1 步：安装 Gopeed

1. 用浏览器打开 Gopeed 官网：`https://gopeed.com/`。
2. 在首页找「下载 / Download」，选择 **Windows** 版本，下载安装包（`.exe`）。
3. 下载完成后双击安装包，一路点「下一步 / Next」直到安装完成。
   - 如果 Windows 弹出蓝色的「已保护你的电脑」提示，点「更多信息」，再点「仍要运行」。这是 Windows 对不常见程序的常规提醒，不是报错。
4. 安装完成后打开 Gopeed。
5. **你应该看到**：一个下载器主界面，通常是左侧或顶部有「任务 / 已完成」等分类，中间是空的下载列表。看到这个界面就说明第 1 步成功了，先不要关闭它。

## 第 2 步：配置 Gopeed 的接口（关键，最容易错）

先解释三个词，不用记：

- **接口（API）**：让别的程序（这里是 DSH）能和 Gopeed 说话的通道。
- **端口**：通道的门牌号，Gopeed 和插件必须用同一个号码。
- **协议**：通道的规矩，这里要用 **TCP**。

操作：

1. 在 Gopeed 主界面，找「设置 / Settings」。它通常在**左下角**或侧边栏，图标是一个齿轮。
2. 在设置里找「**高级 / Advanced**」。不同版本也可能放在「网络 / Network」下面。
3. 找到「**协议 / Protocol**」，选 **TCP**。1.9.3 的协议选项只有 **TCP** 和 **Unix socket** 两种，没有 HTTP，所以不存在选错协议的问题。
4. 找到「地址 / Host / Address」这一项，把它填成 `主机:端口` 的完整形式，例如：

   ```
   127.0.0.1:9999
   ```

   - **注意**：Gopeed 的设置里通常只有**一个**地址框（内容形如 `127.0.0.1:0`），地址和端口是写在一起的，不是分开两个框。所以直接把整串改成 `127.0.0.1:9999` 即可。
   - 如果你的版本恰好把「地址」和「端口」拆成了两个输入框，那就分别填 `127.0.0.1` 和 `9999`。
5. **为什么要把 `:0` 改掉**：Gopeed 桌面版出厂就是 `127.0.0.1:0`，端口 `0` 表示**每次启动随机分配一个端口**，插件无法提前知道。固定成 `9999` 只是本手册的示例值，**不是 Gopeed 的默认值**，你填别的数字也可以，只要插件里填同一个。
   - 如果这一页本来就不是 `0`、已经是一个固定数字，那就直接记下那个数字，后面插件里填同一个。
   - 也可以**完全不改**，让插件自己去检测（插件默认 `port = 0` 就是自动检测）；但固定端口更稳，因为随机端口每次重启都会变。
6. 这里**没有**「启用 API」一类的开关，接口默认就是开着的，不用找。
7. 点「保存 / Save」或「应用 / Apply」。有些版本改完立即生效；为了保险，可以退出 Gopeed 再重新打开一次。

**你应该看到**：设置页里协议是 TCP，地址写成了 `127.0.0.1:9999`（或你选的固定端口），并且保存后这些值没有变回去。

**如果找不到这些选项**：不要自己乱点。直接回到 DSH，对 agent 说：「帮我查一下当前 Gopeed 版本的 API 和协议设置在哪里」。不同版本的界面文字可能略有差异，让 agent 帮你确认最稳妥。

## 第 3 步：Token（可以整步跳过）

Token 就是一把「暗号」，Gopeed 和插件两边必须完全一样。**Gopeed 出厂的 Token 是空字符串，也就是不鉴权；插件默认值同样是空**，所以两边都空着本来就能通，这一步不做也不影响使用。

想开鉴权的话：

1. 回到 Gopeed 的「设置 → 高级」页面。
2. 找到「**Token / API Token**」输入框。
3. 填一个你记得住的词。`deepseek` 只是文档里常用的示例，**不是 Gopeed 或插件的默认值**。
4. 点「保存 / Save」。

**请记住这个词**，第 5 步要原样填进插件。大小写、空格都算数，两边必须**一模一样**。

**如果找不到 Token 输入框**：说明这个版本没有暴露 Token 设置，那就保持两边都不填（即不鉴权），直接进入第 5 步、把 Token 留空即可。

## 第 4 步：在 DSH 里安装插件

1. 回到 DSH 的网页界面，打开任意一个对话。
2. 把下面这句话**整句复制**，发给 agent：

   > 用 plugin_manager 安装 dsh-gopeed 这个 bundle

3. 等 agent 回复。如果它弹出确认或请求批准，点同意。
4. **你应该看到**：左侧「插件」→「已安装」里出现 **`Gopeed 下载器`**。
5. 如果 agent 提示需要重启 DSH，就完全退出 DSH 再重新打开，然后刷新网页。

如果 agent 反问「插件包在哪里」，把它需要的插件文件夹完整路径发过去即可；如果是从插件市场安装，直接说名字就行。

## 第 5 步：填配置

1. 在 DSH 左侧点「插件」，再点「已安装」。
2. 找到 **`Gopeed 下载器`**，点开它，找到行 **`gopeed`**，点「配置」。
3. 按下面填写（**从上往下**，第一项就是新加的「下载位置」）：
   - **下载位置**：三选一，默认「工作区」。
     - **工作区**：存到**当前这个对话的工作目录**里，而且跟着 `working_directory` 切换的目录走（agent 把工作目录切到别的项目，文件就落到新的那个）。适合你想让生成的文件留在当前项目旁边时使用。
     - **Gopeed 默认目录**：插件不传路径，完全交给 Gopeed，用它自己设置里的下载目录。适合你已经在 Gopeed 里配好了下载文件夹。
     - **自定义**：选它之后下面会多出一个「**自定义路径**」输入框，填一个绝对目录，例如 `D:\Downloads`。这个框**默认是空的**，空着保存也能过，但下载会落回 Gopeed 默认目录——输入框下面的提示会写明这一点。
     - 不管选哪个，agent 在调用 `gopeed_add` 时**显式传了 `path`**，就以它传的路径为准。
   - **Gopeed 监听地址**：`127.0.0.1`（默认值；**必填**，留空会被拒绝保存）
     - **只填 IP 或主机名**：不要带 `http://`，也不要把端口写在这里（端口是下一个框）。粘错会被当场拒绝。
   - **端口**：默认 `0`。`0` = 让插件自己去问 Windows 当前是哪个端口；**留空不行**（会被拒绝保存），要自动检测就填 `0`；如果第 2 步在 Gopeed 里固定了端口，这里填同一个数（例如 `9999`）
   - **Token**：第 3 步填的那个词；第 3 步没设就**留空**（两边都不填 = 不鉴权，可以正常用）
   - **程序路径（可选）**：**留空**，插件会自动查找 Gopeed.exe；手填时必须是 `.exe` 文件，填目录会被忽略并回落到自动查找
   - **Webhook 推送**：默认是 `off`，**这一项先不用管**。想开启「下载完成通知」请看第 8 步。
4. **你应该看到**：表单上方「当前请求地址」显示为 `http://127.0.0.1:9999`（端口填 `0` 时预览里显示的就是 `0`，保存后插件会自动检测真实端口）。
5. 点「保存」。**你应该看到**提示「已保存，配置即时生效」。

小提醒：Token 框留空表示「不修改已保存的值」。如果你在 Gopeed 里设过 Token、又不确定插件里存的是不是同一个，就把 Token 重新输入一遍再保存。Token 填错时工具会直接报 `unauthorized` / `the token is wrong`，不会说成「连不上」；看到这句话就回第 3 步把两边对齐，不用去查端口。

## 第 6 步：验证

1. 回到对话，对 agent 说：

   > 调用 gopeed_process 看看 Gopeed 状态

2. **成功的标志**是同时看到这几类信息（文字措辞可能略有不同，关键词对上即可）：
   - 状态 / verdict：`running`
   - API：`ok`
   - 进程：能看到 `Gopeed.exe` 和一个 pid 数字
   - Webhook：`off`（默认，没开推送）或 `manual` / `auto` 加一个监听地址
3. 同一个工具还会返回 Gopeed 的版本号（例如 `1.9.x`）、安装路径，以及插件自己的版本号（`pluginVersion`），能看到这些说明连接正常。如果配置页顶部的版本号比它小，说明浏览器还在用旧界面，重启 DSH 再刷新页面。
4. 如果有任何一项不对，直接看下面的「常见问题」，按编号排查。

## 第 7 步：第一次下载

1. 对 agent 说：

   > 用 gopeed 把 https://example.com/xxx.zip 下载到 D:\Downloads

   把链接换成你真正要下载的地址。这句话里的「下载到 D:\Downloads」就是**显式指定路径**，会覆盖配置页里的「下载位置」。
   如果你不指定路径，就直接说「用 gopeed 下载这个链接」，文件会按第 5 步选的「下载位置」落盘：
   - 选「工作区」→ 存进当前对话的工作目录；
   - 选「Gopeed 默认目录」→ 存进 Gopeed 自己设置里的下载目录；
   - 选「自定义」→ 存进你填的「自定义路径」。
   想给任务起个名字，可以再加一句「名字叫 xxx」（对应 `gopeed_add` 的 `name` 参数）；不起名就由 Gopeed 从链接里取。
2. agent 会调用 `gopeed_add`，并返回一个 `taskId`。**你应该看到**类似「任务已创建」的回复，以及文件的实际保存目录
   （就算你没指定路径，插件也会回读 Gopeed 告诉它文件落在哪）。
   - 创建成功时，agent 还会拿到一个**后台任务**（返回里的 `jobId`）。下载结束时它会收到通知，所以**不需要一直问进度**；
     只有没有后台任务时，回复里才会让你改用 `gopeed_list` 轮询。
3. 想主动看一眼进度：对 agent 说「调用 gopeed_list」。**你应该看到**任务列表，里面有名称、状态、百分比和速度。
4. 也可以说「调用 gopeed_status，id 是 ……」，只看某一个任务。
5. 想看文件有没有下来：打开上面显示的那个保存目录即可（第 7 步第 1 条列出的三种位置之一）。
6. 需要暂停、继续或删除时，直接对 agent 说「用 gopeed 暂停这个任务」「继续」「删掉」，不需要自己操作（对应 `gopeed_control`，`action` 分别是 `pause` / `resume` / `remove`）。

## 第 8 步（可选）：打开「下载完成通知」

默认是关闭的。想让插件在下载完成时给你一个更详细的通知，可以打开它。

> 说明：Gopeed 自己已经会在 Windows 通知中心弹一条下载完成通知。插件这条是**可选增强**（多显示名称 / 大小 / 路径），
> 所以默认关着，避免重复打扰。它只影响给你的 toast，不影响「下载完成自动唤醒 agent」——唤醒靠后台任务，不靠 webhook。

1. 回到插件的「配置」页，找到 **「Webhook 推送（下载完成通知）」**（字段名 `webhookMode`）。
   这一整块收在一个**默认折叠的抽屉**里，点开摘要行右边的「展开」即可。
2. 选 **`manual — 手动配置`**。
3. 在下面的 **「Webhook 监听端口」**（字段名 `webhookPort`）里填一个固定数字，或者点旁边的 **「随机生成」**。
   - `webhookNotify` 在配置里有（默认开，控制要不要给 agent 留上下文），但**页面上没有这个开关**，普通用户不用动。
   - **建议填固定数字**：地址才不会每次重启都变，方便一次填进 Gopeed。
   - 如果这里填 `0`，端口由系统随机分配，地址可能每次不同，所以不建议长期用 `0`。
4. 如果想让插件也弹右下角提示，把同一区块里的 **「右下角通知」**（字段名 `webhookToast`）打开。
   不打开也能收到事件，只是不弹插件自己的 toast。
5. 点「保存」。**你应该看到**：端口填的是具体数字时，「Webhook 状态」里会显示完整地址，形如
   `http://127.0.0.1:2xxxx/webhook`，旁边有「复制」按钮——复制它。
   - 如果端口填的是 `0`，页面**不会显示地址**，只会提示保存后用 `gopeed_events` 查实际地址。所以想复制地址，
     就回上一步填一个具体数字。
6. 切到 Gopeed，打开 **设置 → 开发者 → Webhook 推送**。这里**必须做两件事**：
   1. 打开 **「启用 Webhook」** 开关；
   2. 点 **「添加」**，把刚才复制的地址粘进去。
   - ⚠️ **只加地址、不打开开关，推送不会发出来。** 这是最常见的坑：列表里看起来配好了，实际一条通知都收不到。
7. **重启 Gopeed 才会生效。** 关窗口到托盘**不算**重启（进程还在，用的还是旧配置）。回插件配置页，点红色的 **「重启 Gopeed」** 按钮，确认后等它显示「重启成功」。
   - 这个按钮只负责「强制结束进程、等进程真的消失、重新启动并把接口等回来」，**不保存 Webhook 配置**。保存配置是 `auto` 模式下 `gopeed_events action:"apply"` 或你在 `manual` 模式下手动添加的事。
   - 它是**唯一**的重启入口，会中断正在进行的下载。
   - **agent 不能重启或杀 Gopeed**：`gopeed_launch` 只负责「没跑时启动」，`gopeed_events` 只接受 `apply`。杀进程只能由你点按钮。
8. 之后下载完成时，如果第 4 条打开了「右下角通知」，右下角会出现一个约 6 秒后自动消失的小提示。
   也可以让 agent 调用 `gopeed_events` 查看最近的事件（成功是 `DOWNLOAD_DONE`，失败是 `DOWNLOAD_ERROR`；最多记 50 条，返回后就算已读）。
   - 通知**不会**出现在对话里。插件不会以你的名义发消息；它只会给 agent 的下一轮留一行上下文，不会主动叫醒 agent。
   - 真正能**唤醒空闲 agent** 的是 `gopeed_add` 注册的后台任务，它和 webhook 是否开启无关。

> **`auto — 自动配置` 是什么**：同样会监听，但你可以让 agent 调用 `gopeed_events` 并传 `action:"apply"`，由插件把监听地址保存进 Gopeed 配置（会保留你已有的地址，并回读确认）。它只负责保存配置，**不会**帮你重启 Gopeed，重启仍然要点那个红色按钮。如果你不懂这步，选 `manual` 更直观。

## 常见问题（照着查）

### 1. 显示 `verdict: stopped`（连接被拒绝）

- **现象**：agent 告诉你 Gopeed 没有响应、连接被拒绝。
- **原因**：Gopeed 没打开；或者第 2 步协议没设成 TCP；或者插件里填的端口和 Gopeed 里的固定端口不一致。
- **怎么办**：先确认 Gopeed 正在运行；然后对 agent 说「调用 gopeed_launch」。仍然不行，就回第 2 步逐项核对协议、地址、端口，再把插件端口改成同一个数（或填 `0` 让插件自动检测）。

### 2. 显示 `verdict: unauthorized`

- **现象**：能连上，但提示未授权；错误信息通常带 `code=1001 msg=unauthorized -- the token is wrong; set it in the plugin settings`。
- **原因**：Gopeed 里的 Token 和插件里填的不一致。Gopeed 会回 HTTP 401，插件据此判定 `unauthorized`；这也说明**端口已经被确认是对的**（自动检测不会因为 Token 错就丢掉这个端口），所以别去动端口。
- **怎么办**：回第 3 步看 Gopeed 里的 Token，再回第 5 步重新输入并保存。注意大小写和多余空格。Token 框留空表示「不修改」，所以一定要重新输入一次。

### 3. 显示 `verdict: unresponsive`（端口通但不响应）

- **现象**：端口是通的，但 Gopeed 不说话，通常是程序卡住了。
- **原因**：Gopeed 进程假死。
- **怎么办**：打开插件配置页，点红色的 **「重启 Gopeed」** 按钮，确认即可。它会强制结束进程、等进程真的消失、再重新启动并等接口回来；没下完的任务一般能靠断点续传恢复。**不要**让 agent 去重启——它也做不到。

### 4. 任务建了但不动，速度一直是 0

- **现象**：`gopeed_list` 里能看到任务，但进度不走。
- **原因**：链接本身很慢、资源没有种子，或者网络访问不到，跟插件无关。
- **怎么办**：先用浏览器试试同一个链接能不能打开；换一个链接再试。如果是 BT / 磁力任务，冷门资源本来就可能长时间没有速度。

### 5. 找不到配置入口

- **现象**：在「插件 → 已安装」里找不到 `Gopeed 下载器`，或点开没有「配置」。
- **原因**：插件没启用，或者页面还是旧的。
- **怎么办**：按 `F5` 刷新网页；确认插件处于启用状态；仍然没有就完全退出 DSH 再打开一次。

### 6. 插件找不到 Gopeed 程序路径

- **现象**：`gopeed_launch` 提示找不到 Gopeed.exe。
- **原因**：用的是绿色版，或安装在了非默认目录。
- **怎么办**：在第 5 步的「程序路径（可选）」里填 `Gopeed.exe` 的完整路径。不知道路径时：在桌面 Gopeed 图标上右键 →「打开文件所在位置」，点一下窗口上方的地址栏即可复制文件夹路径，再拼上 `\Gopeed.exe`。这一步仍然不需要命令行。

### 7. 保存后仍提示 Token 不对

- **现象**：确认填了 Token，但一直 `unauthorized`。
- **原因**：保存时 Token 框是空的，插件保留了旧值。
- **怎么办**：重新打开配置页，把 Token 明明白白再输入一遍（不要留空），点保存，再让 agent 跑一次 `gopeed_process`。

### 8. 显示 `verdict: misconfigured`（进程在跑，但接口连不上）

- **现象**：`gopeed_process` 同时告诉你「进程在跑（有 pid）」和「连接被拒绝」，结论是 `misconfigured`。
- **原因**：不是 Gopeed 没启动，而是**端口对不上**。Gopeed 桌面版出厂是 `127.0.0.1:0`（每次启动随机端口），插件猜不到；或者第 2 步改完端口后，插件里填的还是旧值。
- **怎么办**：回第 2 步看 Gopeed 里现在的固定端口，把插件配置页的「端口」改成同一个数字，保存后重跑 `gopeed_process`。或者把插件端口填 `0`，让插件自己去问 Windows 当前端口。
- **为什么不用急着重装 / 重启**：这个结论就是为了避免「进程明明在跑却让你去启动它」这种误导，所以它会直接说清是端口问题。

### 9. Windows 不让插件读端口时，要不要打开 `portScan`

- **背景**：为了自动找到随机端口，插件会先问 Windows「这个 Gopeed 进程在监听哪个端口」（`netstat -ano`，看不到再用 `Get-NetTCPConnection`）。有些环境（权限受限、安全软件拦截）两条路都拿不到结果，这时插件会如实告诉你「端口无法确定」，让你手填。
- **`portScan` 是什么**：一个**默认关闭**的高级选项。注意：**配置页上没有这个开关**，它写在 profile 的 `cordis.patch.yml` 里。
  打开后，插件会在本机动态端口范围内逐个探测，找出真正在响应 Gopeed 接口的那个端口。
- **为什么不是默认开**：它会把本机其它软件占用的端口也连一遍，属于有侵入性的操作，所以做成需要你明确同意才启用的开关。
- **怎么办**：优先按第 2 步在 Gopeed 里固定端口并把同一个数字填进插件；只有在你接受「插件会扫本机端口」时，才让维护者（或你自己）在 profile 的 `cordis.patch.yml` 里打开 `portScan`。

### 10. 下载完成了，但右下角没有通知

按顺序检查：

1. **配置页里「右下角通知」打开了吗？** 它默认关着（`webhookToast`）。Gopeed 自己那条 Windows 通知不受影响，
   但插件这条不会出现。打开它再试。
2. **配置页是不是 `off`？** `off` 默认不监听任何端口，收不到推送。改成 `manual` 或 `auto`。
3. **Gopeed 里「启用 Webhook」开关打开了吗？** 这是最容易漏的一步。只把地址加进列表、开关没开，推送不会发出来。
4. **Gopeed 里真的添加了同一个地址吗？** 地址必须和插件显示的一字不差（端口、`/webhook` 路径都要对）。
5. **改完有没有「完全重启」Gopeed？** 关窗口到托盘不算，必须点插件配置页的「重启 Gopeed」，或者完全退出 Gopeed 再打开。GUI 里可能仍显示旧值，这不代表没保存进去。
6. 还不行就给 agent 说「调用 gopeed_events 看看有没有事件」，或者「调用 gopeed_process 看 Webhook 状态」——`webhookListening`、`webhookUrl`、`webhookReceived` 会告诉你是哪一段没通。

### 11. 「重启 Gopeed」按钮能用 agent 代替吗

**不能。** 0.2.0 起只有一个重启入口：配置页上的红色按钮（会二次确认，且会中断下载）。`gopeed_launch` 只负责「没跑时启动」，没有任何参数能重启；`gopeed_events` 只接受 `action:"apply"`，传别的会被拒绝。这是为了避免 agent 误杀你的下载器。

## 我还需要准备什么

只需要两样东西：能打开网页、能对话的 **DSH**，以及装好的 **Gopeed**。不需要安装 Node.js 或任何包管理器，不需要使用命令行，也不需要手动改任何配置文件。插件由 DSH 自己运行，真正负责下载的是 Gopeed。唯一要记住的，是「Gopeed 里的端口」和「插件里的端口」必须是同一个数——Token 不设也没关系（两边都空 = 不鉴权）。

> 说明：本文按 **0.3.x** 的界面和工具名编写（`gopeed_add`、`gopeed_list`、`gopeed_status`、`gopeed_control`、`gopeed_process`、`gopeed_launch`、`gopeed_events`）。暂停 / 继续 / 删除都走 `gopeed_control`，用 `action` 指定 `pause` / `resume` / `remove`；连通性、版本与 Webhook 状态检查走 `gopeed_process`；下载事件与 Webhook 配置保存走 `gopeed_events`。下载保存位置由配置页的「下载位置」（`downloadTarget`）决定，agent 显式传 `path` 时优先用它的路径。工具名和界面细节以后续版本的 README 为准。
